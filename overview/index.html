📋 Overview

Portionist is a modern, AI-powered mobile and web application designed to help users manage their meal planning, track nutrition, and achieve their health goals. The app combines recipe discovery, personalized meal suggestions, and comprehensive nutrition tracking in one seamless platform.

✅ Production Ready: Fully functional app with backend deployed on Railway and frontend supporting iOS, Android, and Web platforms.

🎯 Core Purpose

  • Personalized Nutrition: Get meal suggestions based on your weight goals, dietary preferences, and cuisine choices
  • Recipe Discovery: Search from thousands of recipes with detailed nutritional information
  • Meal Logging: Track your daily food intake and monitor progress
  • AI-Powered: Generate custom recipes using Google's Gemini AI
  • Cross-Platform: Available on iOS, Android, and Web browsers

📱 Frontend Architecture

  • React Native with Expo: Cross-platform mobile/web development
  • Redux Toolkit: State management for auth, pantry, and favorites
  • React Navigation: Drawer + Stack navigation with auth flow
  • AsyncStorage: Persistent local storage for auth tokens
  • Custom Hooks: Reusable logic for auth restore, onboarding, storage

🔧 Backend Architecture

  • Express.js: RESTful API server with TypeScript
  • Drizzle ORM: Type-safe database queries with PostgreSQL
  • Modular Design: Separated routes, controllers, and utilities
  • API Tracking: Singleton tracker with 24-hour rolling window
  • Error Handling: Centralized error middleware

🗄️ Database Schema

users

Column Type Constraints
user_id UUID PRIMARY KEY, DEFAULT gen_random_uuid()
email VARCHAR(255) UNIQUE, NOT NULL
password_hash TEXT NOT NULL
full_name VARCHAR(255) NOT NULL
created_at TIMESTAMP DEFAULT NOW()
updated_at TIMESTAMP DEFAULT NOW()

onboarding

Column Type Constraints
onboarding_id UUID PRIMARY KEY, DEFAULT gen_random_uuid()
user_id UUID FOREIGN KEY → users(user_id), UNIQUE
current_weight NUMERIC(5,2) NOT NULL
target_weight NUMERIC(5,2) NOT NULL
cuisine VARCHAR(100) NOT NULL
user_age INTEGER NOT NULL
created_at TIMESTAMP DEFAULT NOW()
updated_at TIMESTAMP DEFAULT NOW()

favorites

Column Type Constraints
favorite_id UUID PRIMARY KEY, DEFAULT gen_random_uuid()
user_id UUID FOREIGN KEY → users(user_id)
recipe_id VARCHAR(255) NOT NULL
recipe_title TEXT NOT NULL
recipe_image TEXT
protein NUMERIC(6,2)
carbs NUMERIC(6,2)
fat NUMERIC(6,2)
calories NUMERIC(6,2)
created_at TIMESTAMP DEFAULT NOW()

food_logs

Column Type Constraints
log_id UUID PRIMARY KEY, DEFAULT gen_random_uuid()
user_id UUID FOREIGN KEY → users(user_id)
recipe_id VARCHAR(255) NOT NULL
recipe_title TEXT NOT NULL
meal_type VARCHAR(50) NOT NULL (Breakfast/Lunch/Dinner/Snack)
protein NUMERIC(6,2) NOT NULL
carbs NUMERIC(6,2) NOT NULL
fat NUMERIC(6,2) NOT NULL
calories NUMERIC(6,2) NOT NULL
source VARCHAR(50) DEFAULT 'spoonacular'
logged_at TIMESTAMP DEFAULT NOW()
💡 Note: All tables use UUID for primary keys. Foreign key relationships ensure data integrity. Timestamps track creation and update times.

🚀 Deployment

Backend (Railway)

Production URL: https://portionist-backend.railway.app
  • Platform: Railway.app
  • Database: PostgreSQL on Railway
  • Build Command: npm run build
  • Start Command: node dist/index.js
  • Environment Variables: DATABASE_URL, PORT, API keys

Frontend (Mobile)

  • Platform: Expo Go
  • iOS: Scan QR code in Expo Go app
  • Android: Scan QR code in Expo Go app
  • Development: npx expo start

Frontend (Web)

  • Platform: Web Browser
  • URL: Local development or Netlify/Vercel deployment
  • Command: npx expo start --web

Environment Setup

# Backend .env
DATABASE_URL=postgresql://user:pass@host:port/db
PORT=3000
SPOONACULAR_API_KEY=your_key_here
GEMINI_API_KEY=your_key_here
GOOGLE_SEARCH_API_KEY=your_key_here
GOOGLE_SEARCH_ENGINE_ID=your_id_here

# Frontend (built into app)
API_BASE_URL=https://portionist-backend.railway.app

🔗 External APIs

Spoonacular Recipe API

⚠️ Rate Limit: 150 calls per day (Free tier)
  • Usage: Recipe search, suggestions, nutrition data
  • Endpoints Used: /recipes/complexSearch, /recipes/{id}/information
  • Current Usage: ~60-110 calls/day (tracked in real-time)
  • Fallback: Demo mode with 13 mock recipes when limit reached

Google Gemini AI (1.5 Flash)

✅ Generous Limit: 1,500 calls per day (Free tier)
  • Usage: AI-powered recipe generation
  • Features: Custom recipes based on ingredients, cuisine, goals
  • Current Usage: Minimal (~5-10 calls/day)
  • Model: gemini-1.5-flash

Google Custom Search API

📊 Limit: 100 calls per day (Free tier)
  • Usage: Fallback recipe image search
  • Current Usage: Rarely used (backup only)
  • Status: Configured but not primary

API Monitoring

Track API usage in real-time:

# Get usage summary
curl http://localhost:3000/api/usage/summary

# Get detailed report
curl http://localhost:3000/api/usage/detailed

# Response includes:
# - Calls in last 24 hours

🏁 Getting Started

Prerequisites

Node.js >= 18.x
npm >= 9.x
Expo CLI
Git

Backend Setup

# Clone repository
git clone https://github.com/yourusername/portionist.git
cd portionist/backend

# Install dependencies
npm install

# Create .env file
cp .env.example .env
# Add your API keys and DATABASE_URL

# Build TypeScript
npm run build

# Run migrations
npm run migrate

# Start development server
npm run dev

# Server runs on http://localhost:3000

Frontend Setup

# From project root
cd portionist

# Install dependencies
npm install

# Start Expo development server
npx expo start

# Options:
# - Press 'w' to open in web browser
# - Scan QR code with Expo Go (iOS/Android)
# - Press 'i' for iOS simulator
# - Press 'a' for Android emulator

Database Setup

# Option 1: Railway (Recommended)
1. Create Railway account
2. Create new PostgreSQL database
3. Copy DATABASE_URL to .env

# Option 2: Local PostgreSQL
1. Install PostgreSQL
2. Create database: createdb portionist
3. Set DATABASE_URL in .env
4. Run migrations: npm run migrate
